1. OVERVIEW
------------------------------------------------------------------------------
BlogPilot is a self-hosted, single-operator web application for managing
multiple niche WordPress blogs from one dashboard. It automates keyword
management, content-opportunity discovery, Google Trends monitoring, research,
AI-assisted writing, SEO analysis, image discovery, and WordPress publishing.

Stack:
  - Next.js 14 (App Router) + TypeScript (strict) + React 18
  - Tailwind CSS (custom component layer)
  - Prisma ORM on SQLite by default (provider-swappable to PostgreSQL)
  - Vitest for tests
  - No heavy external runtime services required (self-contained)

7. SECURITY MODEL
------------------------------------------------------------------------------
  - Sessions: bcrypt(12) + HMAC-SHA256-signed HttpOnly SameSite=Lax cookies
    with 7-day expiry; verified on every protected request.
  - Credentials (OpenRouter keys, WP app passwords): AES-256-GCM encrypted at
    rest using APP_ENC_KEY held OUTSIDE the database. Only a boolean
    hasApiKey/hasAppPassword is returned to the browser; redactSecrets() guards
    logs; never sent to the client after initial submission.
  - Site isolation: every service query filters by websiteId; cascade FKs.
  - Input validation: zod on all API bodies; Prisma parameterized queries;
    provider/CSV/WordPress output treated as untrusted data.
  - SSRF: isSafeOutboundUrl() blocks localhost, private/loopback/link-local,
    and cloud-metadata addresses (applied to WP and image-download requests).
  - Audit logging for sensitive actions. .env and DB files are gitignored.
  - Known gaps (documented, not claimed): rate limiting, explicit CSRF tokens,
    CI dependency scanning.

8. INTEGRATION HONESTY
------------------------------------------------------------------------------
  Provider adapters return explicit { ok: true, ... } | { ok: false, error }
  and never fabricate results. Where an automated provider is unavailable
  (Google Trends, research search) the app reports that limitation and
  supports manual CSV import / manual source entry.

  Live-verified vs mock-verified (see docs/AUDIT.md §5):
    - Openverse image search ..... live-verified (real results returned)
    - Wikimedia .................. implemented, mock-tested only
    - OpenRouter ................. implemented, mock/stub-tested only
    - WordPress .................. implemented, mock-tested; live WP untested
    - Google Trends / research ... honest unavailability + manual fallback
    - Rank Math .................. staged detection/mapping, no live WP probe
